geocodebr — piloto de geocodificação

Roteiro de uso para transformar CEPs/endereço em coordenadas e preparar produtos geoespaciais para projetos SOE.

TutoriaisObjetivoAmbientePilotoQualidadeCodexFontes

1. Objetivo do piloto

Validar um fluxo simples e reutilizável:

Entrada tabela com CEPs ou endereços → geocodebr → latitude/longitude + qualidade do pareamento → GeoDataFrame → GeoJSON/GeoParquet → cruzamento posterior com município, bacia, hidrografia, áreas de risco ou comunidades.

O pacote é desenvolvido pelo Ipea e usa como principal base o CNEFE do IBGE. A versão atual documentada é 0.7.0 e está disponível em Python e R.

2. Onde executar

Codex / Code — recomendado para o pilotoInstalar pacotes, criar scripts, rodar testes, gerar arquivos e versionar no GitHub.
Chat — desenho e revisãoDefinir metodologia, campos, regras de QA e interpretar os resultados.
Work — fase posteriorÚtil quando o fluxo envolver várias fontes, planilhas, páginas, relatórios e atualização recorrente.

Primeira execução: o geocodebr baixa dados do CNEFE para cache local. Cada função baixa apenas o necessário; o conjunto completo pode chegar a cerca de 1,2 GB. Planeje espaço e tempo para essa primeira carga.

3. Preparação

No terminal do ambiente Python:

python -m pip install "geocodebr[geo]"
python -m pip install pandas pyarrow
# opcional para bases territoriais oficiais
python -m pip install geobr

O extra geo permite saída como geopandas.GeoDataFrame e é necessário para algumas funções espaciais.

4. Piloto recomendado para amanhã — CEP → coordenadas

Comece por CEP porque é o teste mais controlado. Baixe os arquivos de apoio desta própria pasta:

Baixar amostra CSVBaixar script Python

Depois execute:

python piloto_geocodebr.py

Saídas esperadas:

saida_geocodebr.geojsonPara abrir diretamente no QGIS, navegador/cartografia web ou carregar em Leaflet.
saida_geocodebr.parquetFormato eficiente para análise e integração futura com DuckDB/GeoPandas.

5. Código essencial

from geocodebr import busca_por_cep

ceps = ["70390-025", "20071-001"]

gdf = busca_por_cep(
    cep=ceps,
    h3_res=9,
    resultado_gpd=True,
    verboso=True
)

print(gdf.head())
gdf.to_file("saida_geocodebr.geojson", driver="GeoJSON")
gdf.to_parquet("saida_geocodebr.parquet")

Os resultados usam SIRGAS 2000 (EPSG:4674). Um mesmo CEP pode retornar mais de uma linha; CEP inexistente pode retornar linha sem correspondência.

6. Segunda etapa — endereço completo

Depois do teste por CEP, passe para uma tabela com campos separados, por exemplo:

id,logradouro,numero,cep,bairro,municipio,uf
1,SEPS 702 902,Bloco A,70390-025,Asa Sul,Brasilia,DF

O fluxo é: definir_campos() para mapear as colunas → geocode() para localizar → conferir precisao, desvio_metros, empates e endereço encontrado. Para o primeiro dia, não automatize a aceitação dos resultados: inspecione os casos de menor precisão e os empates.

7. Controle de qualidade mínimo para SOE

Preservar o identificador originalNunca substituir a chave do registro pelo resultado da geocodificação.
Guardar precisão e incertezaManter as colunas de precisão/desvio; não publicar coordenadas sem rastreabilidade do pareamento.
Separar confirmado de aproximadoRegistros de baixa precisão devem receber status próprio para revisão.
Registrar fonte e dataSalvar versão do pacote, versão/cache do CNEFE e data de processamento.
Validar espacialmenteChecar se o ponto cai no município/UF esperados e, quando pertinente, dentro da bacia/área de estudo.
Não expor dado pessoalAntes de publicar no GitHub, remover informações pessoais ou sensíveis; publicar apenas o necessário ao produto técnico.

8. Extensão natural para os projetos SOE

Depois da geocodificação, o fluxo pode crescer para:

endereço/CEP → geocodebr → ponto → município/IBGE → bacia/hidrografia ANA → área de inundação/risco → população/comunidade → painel e CSV de saída.

Para isso, o pacote geobr é um complemento útil: disponibiliza geometrias oficiais brasileiras, inclusive municípios, setores censitários, áreas de risco, unidades de conservação e outras camadas.
